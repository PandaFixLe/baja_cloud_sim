baja无人赛事中高速 LQR+Frenet 规控架构升级计划（精简版 v2）
Context
当前 2.5 m/s 纯追踪控制器无法适应 5-8 m/s 的中高速。升级为：速度自适应 DP 规划 → 路径锁定 → follower 内部 Bezier 平滑 + LQR 控制（前馈+反馈统一 20Hz）→ 五级状态机（调速+控制器切换）。

与 v1 的关键差异：

全链路统一 20 Hz（执行器硬件限制，50Hz 无意义且引入非整数倍延迟）
smoother 不再是独立节点，合并入 follower（消除 /lqr_trajectory hack topic）
高速 NORMAL 用 LQR，CAUTIOUS 及以下切到纯追踪（低速纯追踪成熟可靠）
"强制直行"改为"最小风险机动"（0.5 m/s 缓行 + 前方 2m 碰撞检测）

频率统一为 20Hz 的原因：

执行器 actuator_adapter 只有 20 Hz timer，高于此频率的指令必然丢帧
车辆横摆响应带宽约 1-2 Hz，20Hz 控制已是 10 倍过采样
消除非整数倍频率比（50/20=2.5×）导致的 0-50ms 随机锯齿延迟
纯 Python 下 Riccati 在线求解 + Bezier 平滑在 50ms 窗口内充裕（<3ms）

路径质量保障：直道不锯齿 + 弯道平滑 + 避障一致
这是回答"如何保证过弯避障平滑、直道无锯齿"的核心机制。

机制 1：直道检测 → 跳过 Bezier（含障碍物防误判）
def is_approximately_straight(waypoints, obstacles=None,
    max_lateral_deviation=0.08,    # 收紧到 8cm (原 15cm 会把微避障判为直线)
    max_heading_variance_deg=1.5,  # 收紧到 1.5° (原 3° 会把微弯判为直线)
):
    if len(waypoints) < 3:
        return True
    
    # ★ 关键: 附近有障碍物 → 永远不简化 (防止微避障路径被拉直撞上)
    if obstacles:
        for obs in obstacles:
            for pt in waypoints:
                # 使用真实车辆半长/半宽 (3.0×1.5m / 2)，而非硬编码 0.5
                if point_to_oriented_box_clearance(pt, obs,
                    vehicle_half_length=1.5, vehicle_half_width=0.75) < 2.0:
                    return False  # 障碍物在 2m 内, 不简化
    
    dx = waypoints[-1][0] - waypoints[0][0]
    dy = waypoints[-1][1] - waypoints[0][1]
    length = math.hypot(dx, dy)
    if length < 0.5:
        return True
    for pt in waypoints[1:-1]:
        lateral = abs((pt[0]-waypoints[0][0])*dy - (pt[1]-waypoints[0][1])*dx) / length
        if lateral > max_lateral_deviation:
            return False
    for i in range(len(waypoints)-2):
        h1 = math.atan2(waypoints[i+1][1]-waypoints[i][1], waypoints[i+1][0]-waypoints[i][0])
        h2 = math.atan2(waypoints[i+2][1]-waypoints[i+1][1], waypoints[i+2][0]-waypoints[i+1][0])
        if abs(wrap_angle(h2 - h1)) > math.radians(max_heading_variance_deg):
            return False
    return True
若判定为直线 → 直接对首尾连线做等弧长采样，零锯齿。

机制 2：平滑-验证流水线（拆分为三个独立函数）
def validate_collision(sampled, obstacles, vehicle_half_length, vehicle_half_width,
                       safety_margin):
    """返回碰撞不通过的段索引集合。"""
    fails = set()
    for pt in sampled:
        for obs in obstacles:
            c = point_to_oriented_box_clearance(
                (pt["x"], pt["y"]), obs, vehicle_half_length, vehicle_half_width)
            if c < safety_margin:
                fails.add(pt["segment_index"])
                break
    return fails

def validate_curvature(sampled, max_kappa):
    """返回曲率超限的段索引集合。"""
    return {pt["segment_index"] for pt in sampled
            if abs(pt["curvature"]) > max_kappa}

def retry_fix_segments(segments, collision_fails, curvature_fails):
    """碰撞失败段→线性回退(并验证线性安全); 曲率失败段→缩短控制臂。"""
    for seg_idx in list(collision_fails):
        seg = segments[seg_idx]
        linear_pts = [lerp_point(seg.p0, seg.p3, t)
                      for t in [j/20 for j in range(21)]]
        # 线性也必须安全, 否则保持标记等待最终降速处理
        if all(point_to_oriented_box_clearance(pt, obs, ...) >= safety_margin
               for pt in linear_pts for obs in obstacles):
            replace_with_linear(seg_idx, linear_pts)
            collision_fails.discard(seg_idx)
    for seg_idx in (curvature_fails - collision_fails):
        seg = segments[seg_idx]
        seg.p1 = lerp(seg.p0, seg.p1, 0.7)
        seg.p2 = lerp(seg.p3, seg.p2, 0.7)

def smooth_and_validate(waypoints, obstacles, vehicle_half_length,
                         vehicle_half_width, safety_margin,
                         max_kappa, samples_per_segment=20, max_retries=3):
    """主循环调度: 预滤波→Bezier→retry{采样→验证→修复}。"""
    # 点数<10跳过预滤波, 避免模糊短路径边角
    filtered = prefilter_waypoints(waypoints) if len(waypoints) >= 10 else waypoints
    segments = build_piecewise_bezier(filtered)

    for retry in range(max_retries + 1):
        sampled = sample_piecewise_bezier(segments, samples_per_segment)
        collision_fails = validate_collision(sampled, obstacles, ...)
        curvature_fails = validate_curvature(sampled, max_kappa)

        if not collision_fails and not curvature_fails:
            return sampled, True

        if retry == max_retries:
            break

        retry_fix_segments(segments, collision_fails, curvature_fails)

    # ★ 最终回退: 标记失败段强制限速 1 m/s, 触发事件日志。
    # 不复用旧轨迹 (旧轨迹基于过时位姿, 障碍物关系已变, 大概率同样不安全)。
    log_event("bezier_degraded", collision=list(collision_fails),
              curvature=list(curvature_fails))
    for seg_idx in collision_fails | curvature_fails:
        mark_segment_speed_limit(seg_idx, 1.0)
    return sampled, False
设计决定：不保留旧轨迹复用。原因: 平滑失败意味着当前障碍物关系已很紧张，旧轨迹基于之前时刻的规划和位姿，障碍物相对关系已过时，同样不安全的概率极高。改为直接降速 1 m/s + 事件日志，让外环规划器在下一周期 (≤100ms) 重新规划。这个延迟在 1 m/s 下仅前进 0.1m，安全可接受。

LQR 收敛性保证：不回中心线不振荡
裸 LQR 不保证无振荡——Q_lat >> Q_head 时天然欠阻尼。需要增益后处理。

物理模型 → 二阶系统
Frenet 运动学模型 (小角度): d_dot = v·θ_e, θ_e_dot = v/L·δ
LQR 反馈: δ = -k_d·d - k_θ·θ_e
代入消元 → 二阶 ODE:

d_ddot + (v·k_θ/L)·d_dot + (v²·k_d/L)·d = 0
标准形式: d_ddot + 2ζωₙ·d_dot + ωₙ²·d = 0

ωₙ = v·√(k_d/L)          自然频率
ζ  = k_θ/(2·√(k_d·L))    阻尼比
阻尼条件
ζ	行为	判定
< 1	欠阻尼，正弦衰减，反复穿越中心线	❌ 波浪线
= 1	临界阻尼，最快单调收敛	✅ 目标
> 1	过阻尼，单调收敛但慢	✅ 可接受
举例：L=1.43, v=5, k_d=2.0, k_θ=1.5 → ζ=1.5/(2·√(2·1.43))=0.44 → 欠阻尼，会振荡！

速度+曲率自适应阻尼（含滞回防边界跳变）
def enforce_damping(k_d, k_theta, wheelbase, curvature, prev_damping=0.85):
    """阻尼切换带滞回: abs(κ) < 0.015 → 直道模式, > 0.030 → 弯道模式。
    中间地带保持上一帧值，防止 κ 在 0.02 附近微小波动引起跳变。"""
    if abs(curvature) < 0.015:       # 低阈值进入直道 (R > 67m)
        target = 0.70
    elif abs(curvature) > 0.030:     # 高阈值进入弯道 (R < 33m)
        target = 1.0
    else:
        target = prev_damping         # ★ 滞回区: 保持原值不变

    required = 2 * target * math.sqrt(k_d * wheelbase)
    if k_theta < required:
        k_theta = required
    return k_d, k_theta, target       # 返回 target 供下一帧
滞回区间：κ ∈ [0.015, 0.030] 是盲区，不触发切换，消除曲率微小波动引起 k_θ 跳变→方向盘微颤。

小偏差死区（仅航向，横向不设死区防极限环）
# ★ 死区只加在航向偏差上 (IMU yaw 噪声 0.12° 是主要抖动源)
theta_e_clean = theta_e if abs(theta_e) >= math.radians(1.0) else 0.0

# 横向偏差不设死区 —— 始终保持小增益持续纠正微漂移
# 防止"4.9→5.1cm 阈值穿越 → bang-bang 极限环"
steering_lqr = -k_d * lateral_error - k_theta * theta_e_clean
为什么横向不设死区：若横向也设死区，GPS 1.5cm 噪声 + 路面微坡度会让车辆在 5cm 附近反复穿越阈值，形成"缓慢漂移→突然推一把→归零→再漂移"的 1-3 秒极限环。取消横向死区后，k_d × 5cm ≈ 0.03-0.08 rad (2-5°) 的持续小转角柔和纠正，无 bang-bang 效应。

±5° 反馈不破坏收敛
反馈 δ_fb = clamp(0.3·d + 0.5·θ_e, ±5°) 是对 LQR 的同符号小幅补充。5° 硬限幅 + 小偏差死区共用 → 直道上反馈项几乎恒为零。

闭环控制详细分析
控制闭环（LQR, 20Hz 统一）
传感器: GPS + IMU (1.5cm噪声, 0.12°噪声)
执行器: Gazebo Ackermann 转向 (500Hz底层)
控制器: LQR Riccati + 前馈 δ_ff

通道: GPS→follower(Bezier+LQR+前馈)→cmd_control→actuator→Gazebo→车辆运动→GPS

延迟预算 (20Hz 控制周期):
  odom采样              t₀
  感知发布 gps/yaw       t₀ + 2ms
  DDS 传输               t₀ + 3ms
  follower 回调:
    Bezier+曲率+前馈      t₀ + 5ms  (<2ms)
    LQR Riccati+阻尼      t₀ + 6ms  (<0.5ms)
  Timer 等待 (平均)       t₀ + 31ms (20Hz的一半)
  cmd_control 发布        t₀ + 32ms
  actuator 转换           t₀ + 33ms
  ─────────────────────────────────
  控制延迟 (平均)         ~33ms
  控制延迟 (最坏)         ~55ms
  8m/s 时的空间误差       ~0.26m (平均) / ~0.44m (最坏)
规划闭环（frenet_planner, 10Hz）
通道: 新障碍物/新位姿→DP规划→新路径→commit→follower(平滑+控制)

延迟预算:
  sensor数据全部到达     t₀
  DP 规划计算            t₀ + ~5ms
  committed_path 发布     t₀ + ~6ms
  follower 应用           t₀ + ~55ms (timer等待+处理)
  ─────────────────────────────────
  规划闭环延迟            ~55ms (平均) / ~155ms (最坏)
双层嵌套稳定性： 外环 (10Hz, 100ms) 是内环 (20Hz, 50ms) 的 2 倍，满足分层控制不干扰条件。

时间戳对齐
修正: truth_perception 中 gps.header.stamp = odom.header.stamp (采样时刻)
      而非 now() (发布时刻)

follower 内的对齐+补偿:
  1. 轨迹年龄: age = now - committed_path.header.stamp
  2. 前向补偿: s_compensated = s_current + age × v_ff(s_current)
     其中 v_ff(s_current) 是速度剖面在 s_current 处的规划速度 (非实际速度)
     保护: s_compensated = s_current + age × min(v_ff(s_current), actual_speed + 1.0)
     → 急减速时不会因 age 放大而补偿过冲
  3. 在 s_compensated 处读取 δ_ff, v_ff (前馈可超前)
  4. 反馈 e_lat(s_current) 用当前 s (反馈不超前，避免传感器噪声放大)
  5. 数据新鲜度: 每个话题独立检查 (GPS >200ms→跳过, path >400ms→停车)
五级状态机（带控制器切换）
CAUTIOUS 及以下切到纯追踪——低速下纯追踪跟踪精度与 LQR 无实质差异，逻辑简单可预测。

NORMAL    — LQR,      全速   (≤ base_speed, 默认 5 m/s)
CAUTIOUS  — 纯追踪,   60%限速
DEGRADED  — 纯追踪,   0.4 m/s
SERIOUS   — 纯追踪,   0.1 m/s
CRITICAL  — 制动 0 + Reset (详见下文 Reset 流程)
CRITICAL Reset 完整流程
Reset 不直接跳回 NORMAL（否则车辆在偏差仍大时突然加速，瞬间再次降级）。安全恢复流程：

CRITICAL 进入:
  1. 发布零速 + 零转向 (紧急制动)
  2. planner: 清空 committed_path 缓存
  3. follower: 清空 smoothed_path, 重置 Frenet 状态累积
  4. 进入 1.5s 强制冷却期
  5. 冷却期后, 若偏差满足 SERIOUS 退出条件:
     → 直接升入 SERIOUS (0.1 m/s 纯追踪)
     → 按正常向上恢复规则逐级升回
  6. 若冷却期后偏差仍超 CRITICAL 进入阈值:
     → 保持 CRITICAL, 再次冷却, 最多循环 3 次
     → 3 次后仍无法恢复 → 永久停车 + 事件: critical_unrecoverable
关键安全原则: Reset 后最低恢复到 SERIOUS（0.1 m/s），绝不允许从 CRITICAL 直接跳 NORMAL。

进入条件（从上级降级）
目标状态	触发条件
CAUTIOUS	clearance < 2.5 **OR** κ > 0.08
DEGRADED	|e_lat| > 1.0 m OR |e_psi| > 15°
SERIOUS	|e_lat| > 2.0 m OR |e_psi| > 30°
CRITICAL	|e_lat| > 3.0 m OR |e_psi| > 50°
退出条件（向上恢复，不对称更严格）
目标状态	触发条件（AND 关系）
NORMAL	clearance > 3.5 AND κ < 0.05 AND |e_lat| < 0.3 AND |e_psi| < 5°
CAUTIOUS	|e_lat| < 0.5 AND |e_psi| < 8°
DEGRADED	|e_lat| < 1.0 AND |e_psi| < 12°
SERIOUS	|e_lat| < 1.8 AND |e_psi| < 25°
防抖与冷却
恢复: 连续 10 周期满足退出条件 → 升一级 (防止噪声触发假恢复)
降级: 连续 3 周期满足进入条件 → 降一级 (快速响应真实危险)

def _control(self):
    if not self._inputs_ready(): return self._stop()
    # 1. 时间对齐 + 新鲜度
    s_comp = self._align_timestamp()
    # 2. 委托 bezier_path 模块: 平滑
    ref_path = smooth_and_validate(self.committed_waypoints, self.obstacles, ...)
    if not ref_path: return self._stop()
    # 3. 委托 frenet_state 模块: 计算偏差
    fs = compute_frenet_state(self.position, self.yaw, self.speed, ref_path, self.prev_fs)
    # 4. 委托 state_machine 模块: 判定状态
    self.state = check_warning_enter(fs, self.curvature, self.state)
    # 5. 委托 lqr_solver / legacy_path_control: 计算转向
    if self.state.use_lqr:
        kd, kth = compute_lqr_gain(...)
        kd, kth = enforce_damping(kd, kth, ...)
        theta_e = apply_heading_deadband(fs.theta_e)
        steering = -kd*fs.d - kth*theta_e + feedforward
    else:
        cmd = legacy_path_control(...)
    # 6. ±5° follower 反馈 (同 ref_path 参考系)
    steering += compute_follower_feedback(fs.d, fs.theta_e)
    # 7. 状态机覆盖速度 + 输出限幅 + 发布
    self._publish(clamp(steering), self.state.speed_limit)
端到端延迟预算 (统一 20Hz)
路径	平均	最坏	8m/s 空间误差
控制闭环 (gps→follower→cmd→actuator)	~25ms	~50ms	0.20m / 0.40m
规划闭环 (感知→规划→commit→follower→cmd)	~55ms	~155ms	0.44m / 1.24m
20Hz 设计理由: 执行器只有 20Hz timer，50Hz 输出必然丢帧并引入 0-50ms 随机抖动。20Hz 的 50ms 窗口内 Bezier+LQR 计算 <3ms，充裕。

实施注意事项（设计审计发现）
1. Frenet 参考系必须统一
LQR 反馈和 ±5° follower 反馈必须基于同一个 smoothed_path 的 Frenet 状态。不能用 centerline。

若 follower 反馈基于 centerline、LQR 基于 smoothed_path，当避障路径偏离中心线时二者会产生相反方向的转向指令。
实现：follower 反馈的 lateral_error 和 heading_error 从 compute_frenet_state(smoothed_path) 获取，不再调整基于 centerline 的值。
2. follower._control() 单体膨胀
follower 重写后 _control() 包含 GPS投影 + 坐标转换 + Bezier平滑 + 曲率 + 前馈 + LQR + 阻尼 + 死区 + 速度剖面 + follower反馈 + 状态机 + 时间对齐 + 新鲜度。目标: _control() < 80 行，所有复杂计算 (Bezier、LQR Riccati、Frenet、曲率、阻尼强制) 放入对应模块 (bezier_path.py, lqr_solver.py 等) 并附带单元测试。_control() 仅做管道调度: 获取输入→调用模块函数→发布输出。

3. 坐标系三向转换
follower 内部涉及三套坐标系: GPS (lat/lon→ENU), 世界偏航 (math convention, 0=east +CCW), 导航偏航 (NED, 0=north +CW)。所有转换必须在 follower 的单个私有方法中完成，使用明确命名的变量 (yaw_world, yaw_nav)，禁止裸 pi/2 - yaw 散落各处。

4. 切换防抖取值确认
LQR↔纯追踪切换的不对称阈值:

进入纯追踪: clearance < 2.5 OR curvature > 0.08
回到 LQR: clearance > 3.5 AND curvature < 0.05 (更严格，防振荡)
5. 纯追踪模式下的 Bezier 平滑
纯追踪使用的参考路径已经过 Bezier 平滑。Bezier 严格通过所有原始 waypoints 的端点 (p0, p3)，仅改变中间曲线形状——不会移动 planner 锁定段的终点，因此不会导致与下一轮规划的衔接错位。纯追踪的前视距离算法对平滑前后路径的响应一致（都是用欧氏距离找目标点）。

6. 状态机 clearance 的双源融合
CAUTIOUS 进入条件依赖 clearance，该值从两个来源取最小值以消除滞后：

来源	频率	延迟	说明
/metrics/planned_clearance	10Hz	~100ms	planner 沿整条路径预计算的最小间隙
follower 本地计算	20Hz	~5ms	用当前位姿 + 最新 /obstacle_markers 实时计算 min(point_to_oriented_box_clearance(...))
effective_clearance = min(planned_clearance, local_clearance)
planned_clearance 覆盖全路径前瞻，local_clearance 快速反应障碍物变化。取 min 保证不遗漏。

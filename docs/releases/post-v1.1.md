# v1.1 之后内容清单

> 本文件汇集 v1.1 之后的结构性改进项，按"接口扩展 / 安全契约 / 时间戳治理 / 复用与发布"
> 四类组织。除非显式标注阻塞关系，否则各项之间独立，可按风险与价值自由排序推进。
> 当前总体进度与各项状态见 [`v1.1-status.md`](v1.1-status.md)。

## 一、接口扩展

### BL-1 速度/曲率剖面下放到 follow

- **现策略（v1.1）**：planner 只发几何路径，速度由 follow 自算；
- **升级目标**：planner 顺带给出每点期望速度与曲率（如 `Path.pose.z` 或新增
  `/planned_speed` 话题），follow 改为速度闭环 + 限幅；
- **价值**：远端已知路况，理应给出"这段该多快"，符合"远端规划指导近端控制"的分层理念；
- **前置**：v1.1 跑通。
- **预留接口位**：v1.1-yaml 中即把"是否发送速度/曲率"的开关与字段名约定好，避免后续
  动接口（表现契约不动，仅扩展）。

## 二、安全契约

### BL-2 INFEASIBLE 缓停与低速兜底

- **当前**：`/planner/status = INFEASIBLE` 或路径超时即硬停；
- **升级**：约定"degraded/creep"握手，replanner 可发一条低速可行的兜底路径或显式
  握手信号，follow 侧做减速斜坡而非急停；
- **价值**：替换老结构里状态机的安全角色。

### BL-3 数据超时分级

分别对 `/planned_path`、`/gps/fix`、`/imu/yaw` 设定超时阈值，在 `_control` 中分级
处理（停车 / 减速 / 警告）。

## 三、时间戳治理

### BL-4 planner 端时间戳修复

- 订阅时保存每条消息 `header.stamp`；
- 坐标变换用与感知消息时间戳最接近的位姿（必要时插值/外推）；
- `/planned_path` 打"输入数据时间戳"而非发布时刻；
- `/imu/yaw` 换用带 header 的消息类型（如 `sensor_msgs/Imu`）。
- **价值**：planner 端时间误差会沿 `/planned_path` 一路传到 follow，整链鲁棒性的根；
- **范围**：大结构更新。

### BL-5 follow 端时间戳响应

以 `/planned_path.header.stamp` 替代本地 now()，与 BL-4 配对。

## 四、复用与发布

### BL-6 real/sim 复用的可插拔参考路径

- 仿真：`/reference_centerline`（由 `truth_perception` 发布）；
- 实车：录制的 CSV；

- 与 v1.1-mvp0 的"planner 旁路 CSV 日志"互补——一个写入，一个加载。

- evaluator 增加 Stanley 模式下的横向偏差/CTE 指标；

## 六、与 v1.1 的关系

- v1.1-mvp0 仅做"控制律移植 + 表现契约零变更"，确保融合能跑通；
- v1.1-yaml 在 v1.1-mvp0 之上做"参数真源 + 运行时调参基础设施"，未引入本文件的项；
- 本文件中的各项是"v1.1 跑通且 yaml 规范固化之后再优化"的方向；
- v1.1 的合并基线选择（Q-OPEN）会影响本文件项的实现优先级，例如若基于 v2.1 合入，
  `pid_path_follower` 与 Stanley 控制律的取舍需要先做比较。

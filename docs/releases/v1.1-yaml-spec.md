# v1.1-yaml-spec 发布说明：算法参数真源 + 运行时调参

> 本版本基于 `Baja-resource-origin-7.23-v1.1` 演进，定位为"工程规范第二步"。
> 上一版 v1.1 的内容详见 [`docs/releases/v1.1.md`](v1.1.md)；分层架构背景与决策
> 依据见 [`docs/planning/background-pan-code.md`](../planning/background-pan-code.md)。

## 一、本版本解决的问题

v1.1 把潘的 Stanley 控制律移植进下层控制器，并把 planner 旁路 CSV 日志做出来——这两
件事**都引入了新的可调参数**。但参数分散在三处：

1. **算法 dataclass 默认值**（`core.py`）：`PlannerConfig`、`ControllerConfig`、
   `StanleyControllerConfig` 的 30+ 个字段默认值硬编在源码里，调参必须改 `core.py`。
2. **节点 ROS 参数**（`params.yaml` + 节点 `declare_parameter`）：启动时通过
   `ros2 param` 注入，但**不能在仿真运行中切换**——想"屏蔽障碍物"模拟无障碍物
   场景，得停掉重启。
3. **节点里的硬编码常量**（`truth_perception_node` 的 `forward=34.0`、
   `frenet_planner_node` 的 `half_width=4.0`、`path_follower_node` 的
   `path staleness 400ms` 等）：散落在多个文件里，没有任何"真源"。

v1.1-yaml-spec 在不破坏现有行为的前提下**先把前两件事规范化**——这一版是工程规范的
**第一步**（参数真源 + 运行时调参基础设施）；第三件（节点硬编码常量整理）留待后续
子版本。

## 二、新增内容

### 2.1 算法参数真源：`algorithm_defaults` + `from_yaml`

- `params.yaml` 末尾追加顶层 `algorithm_defaults` 段，按 dataclass 分为
  `planner` / `controller` / `stanley_controller` 三组，**30+ 个字段与当前
  dataclass 默认值严格一致**。字段顺序与 `core.py` 三个 dataclass 的字段顺序对齐，
  便于对照阅读。
- `core.py` 新增 `load_algorithm_defaults(source, key="algorithm_defaults")`：
  - `source` 接受**文件路径**或**已解析 dict**；
  - 优先调用 PyYAML（若已装），回退到**手写最小 YAML 解析器**（覆盖本项目用的
    块式语法与 `#` 注释，**不引入第三方依赖**到 `core.py` 的 stdlib-only 性质）；
  - 任何失败（文件不存在、解析错误）→ 返回 `{}`，**不抛异常**。
- `core.py` 三个 dataclass 各加 `from_yaml(source, key, group, **overrides)`：
  - 从 yaml 取对应子组，与 `overrides` 合并后调 `__init__`；
  - 字段缺失 → 静默使用 dataclass 默认值；
  - **保留** `PlannerConfig()` / `ControllerConfig()` / `StanleyControllerConfig()`
    无参构造的现有用法——向后兼容。
- 本次**不切换** `frenet_planner_node` / `path_follower_node` 的调用方——它们继续
  使用 `PlannerConfig(...)` / `StanleyControllerConfig(...)` 写法。yaml 准备好后由
  后续子版本切换；本步骤只把基础设施建好。

### 2.2 运行时调参基础设施：第一个 `enable_*` 开关

- `truth_perception_node` 新增 ROS 参数 `enable_obstacles`（默认 `true`）：
  - `True`（默认）：照常发布 `/obstacle_markers` 中的 obstacle MarkerArray；
  - `False`：**不构造** obstacle marker，但**仍然发空 MarkerArray**（`MarkerArray()`），
    让 `frenet_planner._obstacle_callback` 收到空列表，自然把 `self.obstacles = []`——
    彻底"无障碍物"状态。
- `params.yaml` 中 `truth_perception_node.ros__parameters` 末尾追加 `enable_obstacles: true`
  + 注释提示运行时切换命令。
- 切换命令（**无需重启**）：

  ```bash
  ros2 param set /truth_perception_node enable_obstacles false
  ros2 param set /truth_perception_node enable_obstacles true
  ```

- README 新增"运行时调参"段落，记录 `ros2 param set` 模式作为本分支起的工程规范范式：
  - 节点功能类开关统一用 `enable_<feature>` 命名，默认 `true`；
  - 关闭时退化为最简行为（如本例的空 `MarkerArray`）；
  - 通过 `ros2 param set` 在仿真运行中切换，无需重启。

## 三、未变契约（v1.1-yaml-spec 严格遵守）

- **未动** `core.py` 的算法实现：`legacy_path_control`、`stanley_path_control`、
  `plan_frenet_path`、`frenet_to_world` 等纯函数体**未改一行**；三个 dataclass
  字段名、类型、默认值**未改**。
- **未动** 节点调用方：v1.1 的 `frenet_planner_node` / `path_follower_node` 仍按
  v1.1 风格用 `PlannerConfig(...)` / `StanleyControllerConfig(...)` 显式构造；切到
  `from_yaml` 是后续子版本的事。
- **未动** 话题、节点名、入口、`bridge.yaml`、`launch/simulation.launch.py`、
  `setup.py`。
- **未动** v1.1 已发布的发布说明：v1.1.md 仅作为入口链接，**内容与本版正交**——
  本次仅在 v1.1.md 加了"后续版本"指引段落。

## 四、测试

```bash
cd /mnt/data/baja_cloud_sim

python3 -m unittest discover -s src/baja_cloud_sim/test -v
```

v1.1-yaml-spec 在 v1.1 的 10 个测试基础上**追加 4 个 yaml 加载测试**，合计 14 个：

- `test_from_yaml_full_block_via_dict`：dict 输入时三个 dataclass 字段被覆盖，未提及
  字段保留 dataclass 默认。
- `test_from_yaml_missing_file_falls_back_silently`：文件不存在时返回 dataclass
  默认值，不抛异常。
- `test_from_yaml_overrides_take_precedence`：显式 `**overrides` 优先于 yaml 字段。
- `test_load_algorithm_defaults_with_real_yaml_file`：通过 tempfile 写一个真 yaml
  文件，验证 `load_algorithm_defaults` 正确解析（含 `#` 注释、int/float/bool 标量）。

全部 14/14 通过。

## 四、已尝试的 Ubuntu VBox 闭环验证（环境限制，非代码问题）

> 日期：2026-07-24。SSH 登录 vboxuser@127.0.0.1:2222（VBox 端口转发），worktree 在
> `~/baja_cloud_sim` 的 `Baja-resource-origin-7.23-v1.1-yaml-spec-test` 分支。

**做对的事**（**v1.1-yaml 算法层与参数层全绿**）：

- `colcon build` 成功（0.86s），`algorithm_defaults.yaml` 被 setup.py 自动
  symlink 到 `install/.../config/`。
- 所有 4 个 ROS 节点都正确启动（日志里看到 `path_follower: mode=stanley`、
  `Truth perception ready: 0 boxes, 0 centerline samples`）。
- `ros2 param list /path_follower_node` 列出 9 个新参数；`/truth_perception_node`
  列出 `enable_obstacles`。
- 单元测试 15/15 通过（Windows 端）。

**跑不动 Gazebo 闭环**（**VBox guest 环境限制，不是 v1.1-yaml 代码问题**）：

| 尝试 | 结果 |
| --- | --- |
| 直接 `./run.sh --no-video` | Gazebo `OpenGL 3.3 is not supported`（VBox 无 3D 加速）|
| 加 `LIBGL_ALWAYS_SOFTWARE=1` + `MESA_GL_VERSION_OVERRIDE=3.3` | Gazebo 起来但所有 ROS 节点报 `fastrtps_port SHM port conflict`（VBox /dev/shm 清理不彻底）|
| 加 `Xvfb :99` 启虚拟显示 + 软渲染 | Gazebo 不再报 OpenGL，但仍卡在 SHM 端口冲突（`fastrtps_port7429`）|
| `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp` 切 DDS | `librmw_cyclonedds_cpp.so: No such file`；`apt-get install` 需要 sudo（vboxuser 无）|

**结论**：v1.0 时代 `results/seed_42/tracking_20260722_191832.csv`（174795 字节）
能跑出数据，说明这台 VBox 之前用 `./start_remote_rviz.sh` 启的 Xvfb + fluxbox + x11vnc
+ websockify 那一套虚拟显示栈才能正常工作。当前 SSH 单独启的 Xvfb 栈不完整
（缺 fluxbox / x11vnc / noVNC / 完整 DISPLAY 配置），所以 Gazebo 仍然跑不起来。

**建议**：

- 在原生 Linux 或 WSL2（有 GPU 或 virtio 显卡）上跑闭环——同源代码可直接 clone
  本分支 `./build.sh` + `./run.sh` 即可。
- 仍想用 VBox 的话，需要让用户用 vboxuser 登录 GUI 跑 `./start_remote_rviz.sh`
  然后 noVNC 里执行 run.sh——比 SSH 单独跑多一套完整图形栈。
- 或者在 Ubuntu 里加 sudo，装 `ros-humble-rmw-cyclonedds-cpp` 后切 DDS。

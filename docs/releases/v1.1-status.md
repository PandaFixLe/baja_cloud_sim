## 三、按优先级建议的下一步

1. **跑通 v1.1-yaml 在 Ubuntu**（验证 Stanley 控制律与 `enable_obstacles` 实际工作）：
   - `./build.sh` + `./run.sh --seed 42 --obstacles 5`；
   - `ros2 param set /truth_perception_node enable_obstacles false` 验证屏蔽障碍物；
   - 与 v1.0 基线 `results/seed_42/tracking_*.csv` 对比，跟踪误差应有改善。
2. **节点调用方切到 `from_yaml`**（BL-C4）：让 yaml 真成为算法参数真源；建议一次只
   切一个节点，先 `path_follower_node`（代码改动小、效果好）。
3. **更多 `enable_*` 开关**（BL-C7 续）：仿 `enable_obstacles` 模式把 `enable_path_log`、
   `enable_road_boundaries` 等纳入运行时调参基础设施。
4. **节点硬编码常量整理**（BL-C8）：先整理 `path_follower_node` 的 400ms staleness
   与 `truth_perception_node` 的 `forward=34.0`、`backward=6.0`，作为工程规范第三步。
